**이번 사례 결과**

키트 zip 1개 → 사이트 5페이지 → **ai-leehyun.vercel.app** 공개

키트를 넘긴 22:22부터 실제 주소 점검이 끝난 22:36까지 14분. 이현님이 직접 한 일은 저장소 만들기, Vercel 버튼 누르기 두 가지였습니다. 비용은 0원입니다.

이 글은 **만든 사이트를 인터넷에 공개하는 과정**만 다룹니다. 디자인을 정하고 시안을 만든 과정은 [공부노트 #002](/notes/002)에 있습니다.

**바이브코딩이란**

코드를 직접 쓰지 않고, 원하는 것을 말로 설명하면 AI가 코드를 만드는 방식입니다. 사람은 무엇을 만들지 정하고, 결과를 보고, 고칠 점을 말합니다.

**이번에 쓴 도구 4개**

| 도구 | 하는 일 | 비유 |
|---|---|---|
| Claude 채팅 | 기획, 디자인 규칙, 글 초안 | 설계 회의실 |
| Claude 프로젝트 (Claude Code) | 코드를 만들고 GitHub에 올림 | 작업실 |
| GitHub | 사이트 코드를 보관 | 창고 |
| Vercel | 창고의 코드를 인터넷 주소로 공개 | 가게 |

**글 속 표시 읽는 법**

> **잘한 점** 이번에 이현님이 잘한 것. 그대로 따라 하면 됩니다.

> **더 좋은 명령** 이렇게 말했다면 더 빨랐거나 더 정확했을 것.

> **주의할 점** 모르고 지나가면 나중에 곤란해지는 것.

## 0단계. 채팅에서 키트를 만들어 둡니다

이번 사례는 Claude 채팅에서 사이트 시안을 먼저 만들었습니다. 시안이 마음에 들자 채팅이 "사이트 이전 키트"를 정리해 줬습니다. 키트는 완성된 사이트가 아니라, 사이트를 만들 재료 묶음입니다.

| 파일 | 내용 |
|---|---|
| `README.md` | 만드는 순서와 붙여넣을 프롬프트 |
| `DESIGN.md` | 색, 글꼴, 페이지별 화면 구성 (PC·폰) |
| `data/` | 타임라인, 공부노트 목록, 프로그램 기록 |
| `content/notes/` | 공부노트 #001 원고 |
| `assets/` | 제로 표정 12개, 파비콘 |

> **잘한 점** 디자인 규칙을 색 코드, 글꼴 크기, 페이지별 순서까지 글로 남겨 둔 것. 그래서 코드를 만드는 쪽이 짐작할 것이 없었고, 처음 만든 화면이 시안과 거의 같았습니다.

## 1단계. 키트를 Claude 프로젝트에 넘깁니다

Claude 프로젝트 채팅창에 상황을 말하고, 키트 zip을 올렸습니다.

![이현님이 키트를 넘기며 배포 방법을 묻는 대화](/notes/003/cap-01-ask.png)

처음에는 Claude가 컴퓨터의 다운로드 폴더를 직접 열어 보려고 했습니다. 컴퓨터가 여러 대 연결되어 있어 실패했고, zip을 직접 올리는 것으로 바꿨습니다.

> **더 좋은 명령** 처음 메시지에 zip을 같이 올리고, 원하는 결과를 끝까지 말하면 한 번에 진행됩니다.
>
> "이 키트(zip 첨부)로 사이트를 만들어서 Vercel 무료 주소로 배포까지 해줘. 내가 직접 해야 하는 단계는 하나씩 알려줘."

## 2단계. 무엇을 받았는지 먼저 확인합니다

Claude는 키트를 열어 보고, 무엇이 들어 있는지와 앞으로의 단계를 먼저 설명했습니다. 그리고 사이트를 누가 만들지 선택지를 줬습니다.

![키트 내용 설명과 선택지 카드](/notes/003/cap-02-kit.png)

> **주의할 점** 키트나 코드에 API 키(`sk-…`로 시작하는 긴 문자)나 비밀번호가 들어 있으면 GitHub에 올리면 안 됩니다. 누구나 볼 수 있게 됩니다. 이번 키트에는 없었습니다. 확실하지 않으면 "이 안에 올리면 안 되는 비밀 정보가 있는지 확인해줘"라고 먼저 물어보세요.

## 3단계. AI가 사이트를 만듭니다

Claude가 키트대로 Astro라는 도구로 사이트를 만들었습니다. 4분 걸렸습니다. 만든 뒤 PC와 폰 화면을 직접 찍어 확인하고, 사람이 해야 할 일 두 가지를 알려줬습니다.

![사이트 완성 알림과 GitHub 저장소 만들기 안내](/notes/003/cap-03-built.png)

실제로 만들어진 화면입니다.

![완성된 AI이현 홈 화면 (PC)](/notes/003/site-pc.png)

> **잘한 점** "1번 완료"처럼 끝난 단계를 짧게 알려준 것. AI는 이현님 화면을 볼 수 없어서, 진행 상황을 말해 주어야 다음 단계로 넘어갈 수 있습니다.

## 4단계. GitHub에 저장소를 만듭니다

GitHub는 코드를 보관하는 창고입니다. 이현님이 직접 한 일은 이것뿐입니다.

1. github.com 오른쪽 위 **+** → **New repository**
2. 이름에 `ai-leehyun` 입력
3. **Create repository**

빈 저장소가 생기자 Claude가 코드를 올렸습니다. 이때 "GitHub 저장소 연결을 허용할까요?"라는 버튼이 한 번 뜹니다. 허용해야 Claude가 올릴 수 있습니다.

> **주의할 점** 저장소를 Public(공개)으로 만들면 코드와 기록 원본을 누구나 볼 수 있습니다. 공개해도 괜찮은 내용이면 상관없지만, 아니라면 Private(비공개)로 만드세요. 비공개여도 Vercel 무료 배포는 됩니다.

## 5단계. Vercel로 공개합니다

Vercel은 GitHub 창고의 코드를 인터넷 주소로 바꿔 주는 곳입니다.

1. vercel.com에서 **Continue with GitHub**로 로그인
2. **Add New → Project**
3. `ai-leehyun` 옆 **Import**
4. 설정은 그대로 두고 **Deploy**

중간에 처음 보는 화면이 떴습니다.

![Vercel 2단계 인증 화면을 물어본 대화](/notes/003/cap-04-2fa.png)

> **잘한 점** 모르는 화면을 그냥 넘기지 않고 캡처해서 물어본 것. 말로 설명하는 것보다 캡처 한 장이 빠르고 정확합니다.

> **주의할 점** 2단계 인증은 지금 건너뛰어도 되지만, 사이트를 계속 운영할 거면 켜 두세요. 켤 때 나오는 복구 코드는 꼭 따로 저장해야 합니다. 폰을 잃어버리면 그것으로만 들어갈 수 있습니다.

> **주의할 점** Vercel 무료(Hobby) 플랜은 개인적, 비상업적 사용을 위한 것입니다. 나중에 사이트에서 유료 상품을 팔게 되면 유료 플랜으로 바꿔야 합니다.

1분쯤 지나 주소가 생겼습니다. **ai-leehyun.vercel.app**

## 6단계. 실제 주소로 점검합니다

주소가 생기면 끝이 아니라, 실제로 잘 나오는지 확인합니다.

![전체 점검 요청과 결과](/notes/003/cap-05-check.png)

> **잘한 점** 배포 직후 "전체적인 점검"을 요청한 것. 만든 쪽이 직접 확인하게 하면, 내가 놓친 페이지까지 한 번에 볼 수 있습니다.

> **더 좋은 명령** 점검할 범위를 말하면 더 정확합니다. 이번 점검은 페이지 내용과 링크 위주였고, 폰 화면은 이현님이 직접 열어 봐야 했습니다.
>
> "폰과 PC 화면, 모든 페이지 링크, 카톡 링크 미리보기까지 점검해줘. 이상한 곳은 사진으로 보여줘."

## 정리. 채팅과 코드는 역할이 다릅니다

다 끝나고 나서 이런 질문을 했습니다. 처음부터 코드 쪽에서 시작했으면 됐을까?

![Claude 채팅과 Claude 코드의 역할을 물어본 대화](/notes/003/cap-06-roles.png)

| | Claude 채팅 | Claude 프로젝트 (코드) |
|---|---|---|
| 잘하는 것 | 생각 정리, 기획, 글 다듬기 | 만들기, GitHub에 올리기, 고치기 |
| 못하는 것 | 파일을 올리거나 배포하기 | 없음. 상의도 똑같이 가능 |
| 이렇게 말하기 | "같이 고민해줘" | "만들어서 올려줘", "아직 만들지 말고 고민만 하자" |

> **잘한 점** 다 끝난 뒤에 "왜 이렇게 했는지, 다음엔 어떻게 하면 되는지"를 물어본 것. 한 번 한 일이 다음부터는 방법이 됩니다.

앞으로 기록을 추가하거나 디자인을 고칠 때는 Claude 프로젝트에 말하면 됩니다. GitHub에 올라가면 Vercel이 1분쯤 뒤 사이트를 자동으로 바꿉니다. 이 글도 그렇게 올라왔습니다.
